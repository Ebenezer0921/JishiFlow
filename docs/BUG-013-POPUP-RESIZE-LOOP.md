# BUG-013：修改备注后提醒弹窗连续缩放和跳动

## 状态与优先级

- 状态：**已确认待开发**
- 优先级：下一版本发布前阻断项
- 发现时间：2026-10-29
- 适用范围：所有 Windows 开发电脑与后续 Codex 接手任务
- GitHub 跟踪：[#3](https://github.com/Ebenezer0921/JishiFlow/issues/3)

本问题不得因为换电脑、切分支、重新打包或已有 release 构建而遗漏。只有完成 Windows 实机复现、代码修复和验收后，才能更新状态；写出代码或静态检查通过不能视为关闭。

## 用户操作与可观察问题

具体页面和位置 → 已到期提醒弹窗，使用“添加备注或修改提醒事项”只修改备注并保存。

可观察问题 → 弹窗在短时间内连续改变宽高和屏幕位置；长标题和备注反复重新换行，右侧滚动区域及底部完成/未完成操作区跟随重排。视频约 2.667 秒内已经出现多个不同尺寸状态，不是一次正常刷新。

对用户任务的影响 → 备注这一低风险编辑会让提醒卡片明显跳动，妨碍阅读和点击，并可能破坏同区域多卡片的稳定堆叠；用户无法相信保存备注后弹窗会保持在原位置。

建议排查 → 重点检查内容尺寸测量、WebView `ResizeObserver`、Tauri 窗口 `set_size`/尺寸请求、CSS 换行宽度和卡片重排之间是否形成反馈循环。该方向是根据现象作出的假设，必须用日志或最小复现确认，不能直接当作根因。

## 复现步骤

1. 创建包含较长标题或备注的提醒，并让它到期显示弹窗。
2. 在弹窗中进入“添加备注或修改提醒事项”。
3. 只改变备注，不改变标题、提醒时间、卡片大小或其他设置。
4. 保存后持续观察至少 10 秒，并记录窗口宽高、屏幕位置和卡片内部布局变化。
5. 在同一区域存在两条以上提醒时重复，检查其他卡片是否被反复重排。

## 验收标准

1. 只修改备注后，提醒弹窗最多进行一次有意的内容刷新；随后 10 秒内窗口宽高和位置保持稳定，不循环缩放、不抖动。
2. 配置的卡片大小档位保持不变。长标题和长备注在内容区换行或滚动，底部完成、未完成、延后和编辑操作固定可见、可点击。
3. 五档卡片大小、常用字号以及 Windows 100%、125%、150%、200% DPI 至少完成代表性组合回归。
4. 同一区域同时显示多条提醒时，编辑其中一条备注不会导致全部卡片反复移动或越界。
5. 关闭后重提醒、应用重启和保存失败路径均不重新触发尺寸循环。
6. 增加针对重复尺寸请求或布局反馈循环的自动化回归检查，并保留 Windows 实机前后证据。
