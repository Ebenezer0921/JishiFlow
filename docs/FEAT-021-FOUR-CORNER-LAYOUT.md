# FEAT-021 四角定位与溢出排列

2026-11-15，v2.5.0 候选。用户已提供完整需求并授权实施，沿用现有栈和交互。

## 行为与验收

- 位置只提供四个角落。按用户最新视觉偏好，使用无文字四角示意格，不显示下方位置名称；保留中文 aria-label、aria-pressed、选中标记和键盘焦点。
- 旧四角保持；五种已移除位置和未知位置加载时迁移为右下。新增 popupOverflow，缺省或未知值使用 smart；overlap 为重叠模式。保存沿用现有 camelCase 设置格式。
- 设置写盘成功后，全部当前卡片在各自当前显示器工作区内改用所选角落，包括手动卡片，恢复自动队列。不创建预览，不改事项数据。失败时不移动窗口，由现有保存错误提示和重试处理。
- 自动队列按工作区和角落分组，累计实际宽高、边距、间距，向上/下排列后向内开列；关闭、完成、推迟或销毁后整理原组。跨屏手动移动进入目标屏队列尾部，不用全局序号偏移其他屏幕。
- 智能模式容纳不下所有列时整组退化为重叠。重叠标题露出距离根据卡片缩放和窗口 DPI 计算；空间过紧时压缩露出距离，新窗口置前。用户点击或键盘操作标题区域可置前；实际移动超过 4px 才启动拖动并脱离自动排列。
- 重排只 set_position。窗口实际大小缓存来自原生窗口；只有原有 popup_resize 命令在实际请求变化时 set_size 当前窗口。前端 fitPopup 测量算法不改，BUG-013 不关闭。

## 用户明确的边界决定

用户选择：如果工作区小到连一张原尺寸卡片都无法容纳，**保留卡片尺寸，允许这种极端情况下部分越界**。此时停靠工作区起点，不改测量或自动缩小。普通可容纳卡片的工作区仍保证不越界。

重叠数量极大时，物理空间无法容纳每张完整标题，露出区会压缩；零剩余空间可能完全重叠。不能宣称无限数量都能保持完整标题可读。

## 实施范围

- Rust：popup_layout.rs 纯物理坐标算法；lib.rs 设置迁移、实际尺寸缓存、按组重排、切角清除手动状态、标题置前、窗口销毁和移动事件。
- 为满足保存失败保持旧状态，使用同目录临时文件写入/sync 后 rename；失败清理临时文件，写盘成功后通知失败不冒充保存失败。没有引入依赖或全量并发编辑协调协议。
- 前端：index.html/settings.css/dialogs.css 的四角和溢出选项；renderer.js 保存时取消预览；popup.js/tauri-bridge.js 区分标题置前与拖动。现有完成/推迟/修改/关闭接口继续使用。
- 稳定性：保留原 Node 检查并增加失败回滚、无预览和拖动阈值检查；Rust 覆盖四角、多列、不同尺寸、负坐标、小工作区、迁移、持久化与原子写入失败。
